01
开始 / OVERVIEW
LZR / DOCS
插件能做什么
插件就是一个 ZIP。解压后真正起作用的文件有两类：清单说明它需要什么，Lua 说明它做什么。
客户端不执行包里的 JavaScript，也不会把 Flutter Widget 交给 Lua，
能做的事都得经过
host
提供的接口。
01 / PROVIDER
接入一个音乐平台
搜索、专辑、歌单、播放地址、歌词、播放上报、一起听。实现
describe
和用得到的操作，平台就会出现在「添加平台」里，界面跟内置平台一样。
02 / HOST
调用宿主能力
host.http
按清单里的白名单发请求，
host.crypto
负责签名，
host.storage_*
存会话。也可以开 TCP 或 WebSocket 连接，
甚至在本机监听端口，给外部前端用。
03 / UI
扩展界面
可以加设置项、插件页面、正在播放页的菜单项，也能提供主题和布局规则。
控件都由宿主绘制，插件只交数据。
边界
插件拿不到 Dart 对象、Flutter Widget、宿主的文件路径、进程和动态库，
也读不到别的插件的数据。这一点没法用配置放开：
Lua 里能看见的只有
host
和你自己返回的 table。

开始 / MANIFEST
SCHEMA 1
清单字段
manifest.json
是插件唯一的声明来源，决定插件叫什么、入口在哪、能访问哪些网络、
在客户端里显示成什么样。字段不合法时整包被拒，而报错不会告诉你是哪个字段，
所以下面这些规则需要逐条对。
id
string
插件唯一标识，
^[a-z][a-z0-9_.-]{2,79}$
：小写字母开头，3–80 位。
建议用反写域名，例如

string
显示名称，非空且不超过 100 字符。

语义化版本，例如

当前只接受

。
运行时每次

入口 Lua 文件，默认

作者或团队名。

声明这个插件实现了哪些能力。客户端据此决定首页模块、菜单入口和要不要广播播放事件。

/
_
。

登录方式：

、

、

、

完整示例

"name": "Example Music",
"version": "1.0.0",
"description": "把 Example Music 接进 Lazer",
"author": "YOUR NAME",

"apiVersion": 1,
"provider": "example",

是 HTTPS 主机的白名单，最多 32 条。每条是一个主机名，
可带端口，也可以用
*.
前缀通配子域。
写法
允许
不允许
api.example.com
恰好这个主机
任何子域、任何其他主机
*.example.com
example.com
及其所有子域
example.org
api.example.com:8443
同主机且端口为 8443
443 或其他端口
*.com
拒绝安装：通配必须落在可注册域名上
通配符后面必须是一个可注册域名。客户端内置了一小张公共后缀表（

、
com.cn
、

等），把

这类写法判为无效；
想覆盖国别域名下的子域，请写完整的

请求必须使用 HTTPS，且 URL 中不能带用户名或密码。

额外允许裸域

本身。
端口不写时要求目标端口为默认 443；写了端口就要求精确相等。
04
开始 / QUICKSTART
HELLO, PROVIDER
第一个插件
最小的插件只需要一个入口文件和一个
call
函数。
下面这份能登录、能搜索、能取歌词，够出现在平台列表里了。
-- main.lua
local api = require("api")
return {
call = function(operation, args)
if operation == "describe" then
return { providers = {
{ id = "example", name = "Example Music",
auth = { "cookie" },
capabilities = { "search", "lyrics" } },
} }
end
if operation == "session" then
local cookie = host.storage_get("cookie")
if not cookie then return nil end
return { id = "me", name = "Example User" }
end
if operation == "loginCookie" then
host.storage_set("cookie", args.cookie)
return { id = "me", name = "Example User" }
end
if operation == "search" then
return api.search(args.query, args.limit or 30, args.offset or 0)
end
if operation == "lyrics" then
return api.lyrics(args.id)
end
error("unsupported operation: " .. tostring(operation))
end,
}
-- api.lua
local M = {}
local BASE = "https://api.example.com"
-- 参数既可以直接给查询串，也可以给 table；table 会被编码成 a=1&b=2
local function encode(params)
if params == nil then return nil end
if type(params) == "string" then return params end
local parts = {}
for key, value in pairs(params) do
parts[#parts + 1] = host.url_encode(tostring(key))
.. "=" .. host.url_encode(tostring(value))
end
return table.concat(parts, "&")
end
-- host.http 返回 {status, headers, body}，状态码由插件自己解释
local function send(method, path, query, payload)
local url = BASE .. path
local params = encode(query)
if params and params ~= "" then url = url .. "?" .. params end
local body, contentType = nil, nil
if type(payload) == "table" then
body, contentType = host.json_encode(payload), "application/json"
elseif type(payload) == "string" then
body, contentType = payload, "application/x-www-form-urlencoded"
end
local response = host.http({
url = url,
method = method,
headers = {
["Cookie"] = host.storage_get("cookie") or "",
["Content-Type"] = contentType or "application/json",
},
body = body,
})
if response.status ~= 200 then
return { error = { code = 40, httpStatus = response.status } }
end
return host.json_decode(response.body)
end
function M.get(path, query) return send("GET", path, query) end
function M.post(path, payload) return send("POST", path, nil, payload) end
function M.search(query, limit, offset)
local body = M.get("/search", { q = query, limit = limit, offset = offset })
if body.error then return body end
local songs = {}
for _, item in ipairs(body.songs or {}) do
songs[#songs + 1] = {
id = tostring(item.id),
title = item.name,
artists = { { id = tostring(item.artist.id), name = item.artist.name } },
albumId = tostring(item.album.id),
albumName = item.album.name,
coverUrl = item.album.picUrl,
durationMs = item.duration,
}
end
return { songs = songs }
end
function M.lyrics(id)
local body = M.get("/lyric", { id = id })
if body.error then return body end
-- 返回候选数组；客户端解析 LRC 后就得到时间轴
return { { synced = true, lrc = body.lrc } }
end
return M

06
运行时 / ENTRY
CALL CONTRACT
入口与 call 契约
入口文件只执行一次，必须
return
一个 table，
call
是其中唯一的入口函数。
此后宿主的所有调用都走它：平台操作、事件回调、计时器。
return {
call = function(operation, args)
-- operation: string
-- args: table（普通平台操作一定带平台 ID）
return nil
end,
}
位置
内容
operation
操作名，字符串。大小写敏感，按文档写成驼峰或全小写。
args
参数表。由客户端发起的调用会额外带上
args.platform
（即清单里的
provider
）；事件回调带各自的字段，见
事件回调
。
返回值
任意可跨边界的数据，见下方类型规则。返回
nil
表示「没有内容」，不是错误。
可以跨边界的数据
Lua 与宿主之间只能传
nil
、布尔值、数字、字符串、数组和字符串键表。
函数、协程、userdata 跨边界会直接报错
Only data can cross the plugin boundary
。
规则
限制
嵌套深度
48 层
单表键数
100000
表的键类型
只能是字符串或整数；其它类型报
Invalid table key
数组语义
整数键恰好覆盖
1..n
时按数组处理，否则按字符串键表处理
数字
整数保持整数，浮点保持浮点；
NaN
与无穷不可传递
注意
返回值里不要放函数或循环引用。序列化会失败，整次调用报错，
界面上只会说「插件请求失败」，你的错误信息到不了用户。
分发写法
两三个操作用
if
就够了。多起来之后可以按表分发，少一层缩进，
未实现的操作也能一起兜住：
local handlers = {}
handlers.describe = function(args) ... end
handlers.search   = function(args) return search(args.query) end
handlers.lyrics   = function(args) return lyrics(args.id) end
return {
call = function(operation, args)
local handler = handlers[operation]
if not handler then
error("unsupported operation: " .. tostring(operation))
end
return handler(args or {})
end,
}
提示
未实现的操作直接
error
报出来，别静默返回
nil
。
客户端解析失败只会说「插件返回了无效数据」，出错的位置只有你自己的错误信息能说明。
07
运行时 / LIFECYCLE
INSTALL → LIVE
生命周期
从 ZIP 到能用，中间是串行的几步。任何一步失败，已经装好的旧版本都不受影响：
客户端只在临时目录里验证通过之后才替换。
解包与校验
检查 ZIP 体积、文件类型、路径安全性、清单字段，并确认
entry
指向的文件存在。
这一步不执行任何 Lua。
临时 VM 启动
在隔离环境里加载入口、跑一遍 bootstrap。入口必须返回 table 且带
call
字段。
启动有 40 秒上限。
替换与注册
启动成功才替换旧版本。停用、更新或卸载前，客户端会先停掉该插件的请求和关联播放会话。
describe
插件启用后客户端调用
describe
，据此得到平台列表、名称、登录方式与能力。
旧式单平台插件可以省略它，改用清单里的
provider
/
capabilities
/
auth
。
注册扩展
设置项、插件页面、播放器菜单项在入口执行时注册。注册是幂等的：
同一个插件里用相同的
id
再注册一次，更新原项，不会多出一条。
会话与调用
session
返回已登录账号或
nil
。之后每次搜索、取流、取歌词都是一次
call
，同一个插件的调用串行执行。
状态与持久化
会话、设置值、文件沙箱都按插件和平台分开存放。多平台插件必须用
args.platform
区分凭据，不要用一个全局 Cookie 覆盖所有账号。
选择本地音乐不会触发
logout
，切换平台也不会清空其他平台的会话。
说明
logout
只清除当前
args.platform
的凭据。要清空整个插件的数据，
用
host.storage_clear()
，或让用户在插件管理里卸载。

各 10 秒。这样一次卡住的上报不会堵住下一条取流请求。
stream
是用户在等的那一次调用，用默认预算，并且超时后客户端会在新 VM 上重试一次。
注意
指令预算比看起来容易用完。不要在

里对几千条数据逐条拼字符串或做嵌套排序，
批量数据交给

，由宿主完成。
死循环会以「插件响应超时，已自动重启插件」结束：会话还在，这次调用丢了。

运行时 / ERRORS
FAILURE SEMANTICS
错误与超时
错误分两层：Lua 抛出的错误会让当前调用失败；返回一张
{ error = { ... } }
表则是「预期内的失败」，客户端会据此提示用户重试或重新登录。
写法
客户端行为
error("boom")
调用失败，界面提示「插件请求失败」。错误文本不会直接展示给用户。
return { error = { code = 40 } }
识别为登录态失效，提示重新登录。
return { error = { code = 40, httpStatus = 401 } }
同上；
httpStatus
优先于
code
里的状态码。
return nil
合法的「没有内容」：未登录、无歌词、无结果。不是错误。
把 HTTP 失败变成可读的错误
local response = host.http({ url = url, headers = headers })
if response.status ~= 200 then
-- 401/403 交给客户端走重新登录，429 交给重试，其余按服务端故障处理
return { error = { code = response.status, httpStatus = response.status } }
end
说明
code
落在 400–599 之间时会被当作 HTTP 状态解释。业务错误码请用范围外的数值，
例如
code = 70
表示当前歌曲不可用。
用 pcall 处理宿主错误
host.*
在参数非法、权限没给、目标越权时都抛 Lua 错误。
可能失败的调用包在
pcall
里，沙箱的
pcall
是异步版本，
能包住会挂起的
host.http
。
local ok, result = pcall(host.http, { url = "https://api.example.com/ping" })
if not ok then
host.log("warn", "request failed", { reason = tostring(result) })
return nil
end
return result

列表只有第一页
最后一页返回了满
limit
条，客户端以为还有下一页。少返回一条，或如实按分页切片。
请求随机超时
单次调用有 40 秒墙钟和 25 万条指令两道预算，超时后 VM 会重建。
常见原因是循环里逐条拼字符串，或者在一个
call
里串了几十个 HTTP 请求。
Web 版功能缺失
浏览器不能监听端口，所以
socket
系列不存在、
websocket_server
报不支持。用
host.info().features
判断后再降级。
更新之后权限又弹了一次
插件更新会重置按插件存储的授权，这是有意的：避免旧授权被新代码直接复用。
把功能设计成「用户点了才申请」，这类弹窗就不会打断使用。
装上了但什么都没发生
先看插件管理里有没有「插件启动失败」。启动时入口必须
return
一个带
call
的 table，且
require
的模块路径要与 ZIP 内的层级一致。
